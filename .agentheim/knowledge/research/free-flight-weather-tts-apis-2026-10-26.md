# Research: external API assumptions for PlanesAbove

Legend: VERIFIED = confirmed on a primary source (official docs, source code, live call on 2026-10-26). CONTRADICTED = primary or near-primary source says otherwise. UNVERIFIED = could not reach a primary source, or only secondary/user reports exist.

## Question
Do the architect's from-memory assumptions about free flight, route, weather, reference-data and TTS sources hold, for private non-commercial home use (30 s polling, ~30 km radius in Germany, maybe open-sourced later)?

## Summary
- **adsb.lol holds as primary source.** Keyless point query verified live; ODbL 1.0. API key is announced as a future requirement ("obtained by feeding"), not enforced today. The radius is an integer in nautical miles (30 km = 16.2 nm, use 17).
- **airplanes.live assumption is CONTRADICTED.** Multiple GitHub issues (Aug-Oct 2026) report it now returns 403 to every IP that is not a feeder; the official api-guide could not be fetched (403 to our fetcher), so this is user-reported, not primary. Do not use it as a keyless secondary. The "1 req/s" figure is attributed in the only primary text we got to api.adsb.one, not airplanes.live.
- **OpenSky: auth model changed.** OAuth2 client credentials only; basic auth no longer accepted; anonymous = 400 credits/day (per IP); registered = 4000/day. At 30 s polling (2880 calls/day), anonymous is far too small; registered (4000/day) is borderline OK for a 1-credit small bbox. Research/non-commercial only.
- **Routes:** adsb.lol `POST /api/0/routeset` exists, keyless, with a plausibility flag (verified in source). adsbdb `/v0/callsign/{cs}` exists and works keyless, but its route data carries a "may not be copied, published, or incorporated into other databases" restriction (relevant for open-sourcing/caching).
- **Weather:** Open-Meteo works keyless, fields verified live; free for non-commercial use, CC BY 4.0 with required attribution link. Bright Sky is keyless, no stated rate limit, "free-to-use for all purposes"; DWD terms apply.
- **TTS:** rhasspy/piper is archived (Oct 6 2025) -> OHF-Voice/piper1-gpl (GPL-3.0). German thorsten and kerstin voices are CC0. ElevenLabs free = 10,000 credits/month, non-commercial, attribution required for published content. iOS Safari `speechSynthesis` is unreliable for German on iOS 16+/18 and audio playback must start from a user gesture, so server-side Piper WAV/MP3 plus a "tap to enable sound" gesture is the safer design.

## Findings

### 1. adsb.lol (positions)
- **Point endpoint: VERIFIED.** OpenAPI lists `GET /v2/point/{lat}/{lon}/{radius}` (alias `GET /v2/lat/{lat}/lon/{lon}/dist/{radius}`), "up to 250 nm" [1]. A live keyless call to `https://api.adsb.lol/v2/point/50.0/8.5/25` returned aircraft [2].
- **Radius is an integer in nautical miles: VERIFIED** from source: `min(int(...), 250)`, so decimals are truncated (0.9 becomes 0) [3]. 30 km = 16.2 nm; use 17.
- **Top-level response keys: VERIFIED live** `ac, msg, now, total, ctime, ptime` [2]. A live sample entry had: `hex, type, flight` (padded with trailing spaces, e.g. "ABR4UE  "), `r` (registration), `t` (type, e.g. "AT76"), `alt_baro`, `alt_geom`, `gs`, `track`, `baro_rate`, `geom_rate`, `category` ("A2"), `lat`, `lon`, `seen_pos`, `dst`, `dir`, `squawk`, `emergency` [2]. The MLAT sample entry lacked `category`, `alt_geom`, `geom_rate`; `r`/`t` were present [2]. Only `hex, messages, mlat, rssi, seen, tisb, type` are required in the response model; all else optional [4]. Adapters must tolerate missing fields.
- **Units: VERIFIED** (readsb JSON doc): `alt_baro` ft (or string "ground"), `gs` kt, `baro_rate`/`geom_rate` ft/min, `dst` nautical miles, `dir` degrees true from the query point [5]. Note `dst` is only added for circle/closest style queries [5]. The ADR already says selection is computed from the normalised model, which is right.
- **API key: PARTLY VERIFIED.** Repo README: no key required yet; "you will require an API key" in the future, obtained by feeding adsb.lol [6]. Landing page: "the API is available to everyone"; keys can be requested at /request [7]. The request form asks the requester to explain ODbL compliance and (for commercial users) a budget; email must be verified within 24 h [8]. No evidence of a 2026 enforcement change was found (search found none; last repo push seen 2026-03-13 per a search snippet, UNVERIFIED) [6].
- **Rate limits: PARTLY VERIFIED.** README: "dynamic based on the environment load"; 4xx means you are doing something wrong [6]. Some mirrors/search snippets say "no rate limits currently"; the two statements differ (probably older vs newer README) [6]. No numeric limit documented. 1 request per 30 s is well inside any plausible limit.
- **License: VERIFIED** data license ODbL 1.0 [7]; API source code BSD-3-Clause [6]. ODbL requires attribution and share-alike for derived databases; the docs do not spell out an attribution wording [7]. A visible "Data: adsb.lol (ODbL 1.0)" credit is the safe reading (inference).

### 2. airplanes.live (positions)
- **Endpoint shape (`/v2/point/[lat]/[lon]/[radius]`, up to 250 nm): VERIFIED only on api.adsb.one's archived README** [9] and on a third-party script that used `https://api.airplanes.live/v2/point/<lat>/<lon>/<radius>` [10]. Our own live call and the official api-guide returned HTTP 403 (could be bot-blocking or the new access policy) [11].
- **Keyless/public access: CONTRADICTED (user reports, not official).** FlightTracker issue #123 (opened 2026-10-20): "airplanes.live moved their API to be contributor-only", calls from an IP that is not feeding "will always return a 403"; change dated September 2026 [12]. Skylight issue #66 (2026-08-20 to 2026-10-05): "airplanes.live returns 403 to everyone who isn't feeding them" [13]. Airplanes-live-app issue #148: maintainer says access is now via "an extra server in front of the API", default limits removable by running a feeder [14]. A search synopsis also quotes an operator statement that the free API was taken down for excessive use and that keys continue to go to app developers, researchers, etc.; I could not retrieve that statement's source page (UNVERIFIED) [15]. No official airplanes.live announcement was reachable.
- **"1 req/s": UNVERIFIED for airplanes.live.** The only primary text with this wording is the README for ADSB One (api.adsb.one): "rate limited to 1 request per second"; that repo is archived (2026-04-29) and named "api-archive" under the airplanes-live org [9]. A search synopsis says the official guide also says 1 req/s and "Non-Commercial Use, No SLA" but I could not open it [15]. A 2026-07-09 blog says access "is typically earned by running a feeder" and terms lean non-commercial [16] (secondary, vendor blog).
- **Conclusion:** treat as not available to a non-feeder household. Optional: only if the user runs a feeder on the same IP.

### 3. OpenSky Network
- **Auth: VERIFIED.** Only OAuth2 client-credentials; "Basic authentication with username and password is no longer accepted"; token valid 30 min [17].
- **Credits: VERIFIED.** Anonymous: 400 credits/day per IP, latest data only, 10 s resolution. Standard registered user: 4000/day; active feeder (>=30% uptime): 8000/day; licensed: 14,400/hour. Separate buckets for `/states/*`, `/tracks/*`, `/flights/*`. 429 on exhaustion with `X-Rate-Limit-Retry-After-Seconds` [17].
- **`/states/all` bbox: VERIFIED.** Params `lamin, lomin, lamax, lomax`; credit cost by area: <=25 sq deg = 1 credit (a 30 km box is far under) [17]. Optional `extended=1` adds the aircraft category [17]. At 30 s polling = 2880 calls/day: exceeds anonymous 400, fits registered 4000.
- **Terms: VERIFIED.** API "for research and non-commercial purposes"; no commercial data; commercial use requires contacting OpenSky; multiple accounts are banned for life; hyperscaler IPs may be blocked [18]. The full terms-of-use page returned 503; secondary copies suggest binding terms under Swiss law (UNVERIFIED) [19].
- No type (`t`), registration or route in `/states`; only icao24/callsign/position/velocity (not verified field-by-field here).

### 4. Route lookup
- **adsb.lol `POST /api/0/routeset`: VERIFIED.** Listed in OpenAPI; body `{"planes":[{"callsign","lat","lng"}]}` (all three required per plane) [1][4]. Per source: empty list or >100 planes returns HTTP 400; each route is checked for plausibility against the plane's position; unknown routes come back with `airport_codes: "unknown"`; duplicates by callsign collapse; the plausible flag is cached with the first request's position and not re-evaluated for cache hits [20]. Plausibility test: position within max(50 nm, 20% of A-B distance) of airport A or of a (simplified, heuristic) cross-track estimate; code review shows airport B is not tested directly and the cross-track math is approximate [21]. So `plausible: true` is a weak filter; treat as necessary, not sufficient. Key: none required today (same status as section 1) [6]. Data origin: VRS standing data formatted for routes [22]. The exact response JSON schema is not documented in the OpenAPI (returns "string") and I did not make the POST call (UNVERIFIED field names).
- **adsbdb `GET https://api.adsbdb.com/v0/callsign/{callsign}`: VERIFIED live.** Keyless; returns `flightroute` with `callsign_icao/iata`, `airline{name,icao,iata,country,country_iso,callsign}`, `origin`/`destination` with `icao_code, iata_code, municipality, name, lat/lon, country` [23]. Unknown callsigns return 404 [24]. **Rate limits: not documented** in the README [24]. Note the base host is `api.adsbdb.com` (the `www.adsbdb.com` docs page did not render for us) [23][24].
- **adsbdb data quality/terms: VERIFIED.** Flightroute data is from David Taylor (Edinburgh) and Jim Mason (Glasgow) and "may not be copied, published, or incorporated into other databases without the explicit permission of David J Taylor"; midpoints only for a few routes; errors reported through issues [24]. Code is MIT, but this data restriction is separate [24]. Caching responses locally for personal use is probably fine; shipping a prefilled route DB in an open-source repo would not be (inference, not a legal opinion).
- **Both route sources are callsign-based, not flight-based:** The VRS standing-data repo is "user-submitted" CC0 CSV (aircraft, airlines, airports, code-blocks, countries, model-type, registration-prefixes, routes), with corrections via the SDM site [25]. No official coverage statistics found; the architect's "sometimes wrong" caveat stands but is UNVERIFIED quantitatively.

### 5. Weather
- **Open-Meteo: VERIFIED.** Terms: free API for non-commercial use only; "Less than 10'000 API calls per day, 5'000 per hour and 600 per minute" (free tier also 300,000/month); per IP and application; private apps and "personal home automation" explicitly non-commercial; may block misuse without notice; no API key mentioned [26]. License CC BY 4.0: link "Weather data by Open-Meteo.com" beside displayed data, link to CC BY 4.0, indicate changes [27]. Live call `https://api.open-meteo.com/v1/forecast?latitude=50&longitude=8.5&current=weather_code,cloud_cover,visibility,is_day` (no key) returned `weather_code`: 3 ("wmo code"), `cloud_cover`: 94 (%), `visibility`: 30520.00 (m), `is_day`: 0, `interval`: 900 s [28]. Docs list `weather_code`, `cloud_cover`, `is_day`; visibility is available as a "current" variable (hourly variables are all available as current) [29]; confirmed by the live call [28]. Current values update only every 15 min (`interval: 900`) [28]; polling every 30 s is wasteful, poll every 10-15 min.
- **WMO code list: VERIFIED** (Open-Meteo subset): 0 clear, 1 mainly clear, 2 partly cloudy, 3 overcast, 45 fog, 48 depositing rime fog, 51/53/55 drizzle light/moderate/dense, 56/57 freezing drizzle, 61/63/65 rain slight/moderate/heavy, 66/67 freezing rain, 71/73/75 snowfall, 77 snow grains, 80/81/82 rain showers, 85/86 snow showers, 95 thunderstorm, 96/99 thunderstorm with slight/heavy hail (only models with explicit hail forecast, e.g. DWD ICON) [29]. Open-Meteo returns only numeric codes; German text mapping must be done by us [29]. The page also lists 97 "heavy thunderstorm" in the table; this differs from the standard WMO 4677/4680 set, so keep the mapping tolerant of unknown codes [29].
- **Bright Sky: VERIFIED.** "No API key required"; "free-to-use for all purposes"; DWD Terms of Use apply to all data; no uptime guarantee; no rate limit stated; handles >2M requests/day [30]. Code MIT [31]. Live `GET https://api.brightsky.dev/current_weather?lat=50&lon=8.5` (keyless) returned `weather` with `condition` ("dry"), `icon` ("cloudy"), `cloud_cover` (100), `visibility` (37076), `temperature`, wind, precipitation, plus a `sources` entry with station distance (3261 m) [32]. Units are not stated in the response; `condition`/`icon` are text categories, not WMO codes [32]. DWD attribution: reuse of basic-supply data allowed with source reference (e.g. "Quelle: Deutscher Wetterdienst", modified: "Datenbasis: Deutscher Wetterdienst, eigene Bearbeitung") per a search synopsis of the DWD copyright page and GeoNutzV; I could not open the DWD page itself (UNVERIFIED) [33]. Observation is by nearest DWD station (here 3.3 km), which is a real measured value, not model grid [32].

### 6. Type code, airline and category datasets
- **ICAO Doc 8643: UNVERIFIED terms.** The ICAO publication pages returned 403. A search snippet shows ICAO sells/serves Doc 8643 through a paid/API data service and carries a copyright notice with Terms & Conditions; reuse terms not read [34]. Do not redistribute an ICAO-derived table without checking; prefer CC0/ODbL derived sources below.
- **OpenFlights airlines.dat: VERIFIED.** Databases under ODbL; contents under Database Contents License; use with acknowledgement; publicly available derived works must be freely licensed; "commercial use of data ... requires a separate license from OpenFlights" (page wording). Fields: ID, name, alias, IATA, ICAO (3-letter), callsign, country, active (Y/N). Airline data dates from Jan 2012; "Active" flag unreliable; user-added rows may have null codes [35]. Fine for private/open-source non-commercial use, but stale for newer airlines.
- **VRS standing-data (alternative, better): VERIFIED license CC0-1.0** on GitHub; folders include `airlines`, `model-type`, `aircraft`, `routes`, `registration-prefixes`; schemas not read [25]. Currently maintained community data (also what adsb.lol uses for routes [22]). Recommended candidate for ICAO designator -> airline/type, pending a schema look.
- **tar1090-db / Mictronics: license UNVERIFIED.** Repo has no LICENSE file visible and README states no terms; data "maintained by Mictronics" [36]. A downstream project claims ODC-By 1.0 (secondary) [37]. Mictronics' own page returned 404 [38]. Live adsb.lol responses already carry `r`/`t` from the DB, so a local aircraft DB may not be needed for positions at all [2].
- **ADS-B emitter category: VERIFIED** (mode-s.org, which is a secondary technical reference, consistent with readsb "A0 - D7" field description [5]): A0 no info; A1 light (<7,000 kg); A2 medium 1 (7,000-34,000 kg); A3 medium 2 (34,000-136,000 kg); A4 high-vortex aircraft; A5 heavy (>136,000 kg); A6 high performance (>5 g, >400 kt); A7 rotorcraft. Set B: B1 glider, B2 lighter-than-air, B3 parachutist, B4 ultralight/hang-glider/paraglider, B6 UAV, B7 space vehicle [39]. Mapping to WTC: L = A1, M = A2/A3, H/J = A5 [39]. The architect's wording "A1-A7" is correct; note many aircraft transmit no category (seen in the MLAT sample [2]).

### 7. Text-to-speech
- **Piper status: VERIFIED.** `rhasspy/piper` was archived by owner on Oct 6, 2025 (MIT); "Development has moved" to `OHF-Voice/piper1-gpl` [40]. Successor: GPL-3.0, Open Home Foundation "looking for maintainers" [41]. PyPI `piper-tts` 1.8.0 released 2026-09-04, GPL-3.0-or-later, Python >=3.9, wheels for Linux x86-64 and ARM64 [42]. Built-in HTTP server: `python3 -m piper.http_server -m <voice>` on port 5000, `POST /synthesize` returns WAV [43]. GPL-3.0 matters for redistribution (container image) and if the project is later published; calling it as a separate process/service is the usual way to keep your own code license free (inference, not legal advice).
- **German voices: VERIFIED.** `rhasspy/piper-voices` has `de_DE`: eva_k, karlsson, kerstin, mls, pavoque, ramona, thorsten, thorsten_emotional [44]. Thorsten medium (22,050 Hz): CC0 [45]. Kerstin: CC0 [46]. Voice licenses are per voice in MODEL_CARD; some voices may be restrictive; Piper docs say "intended for personal use and text to speech research" with no extra restrictions of their own [47]. Check MODEL_CARD of any other voice (eva_k, karlsson, ramona, pavoque, mls not checked).
- **CPU suitability on x86 mini PC: UNVERIFIED with numbers.** No primary benchmark found; docs only say "fast, local" and ship Linux x86-64 wheels [42]. Plan to measure real-time factor on the ZimaOS box; a one-sentence announcement every 30 s is a tiny workload (inference).
- **ElevenLabs free tier: PARTLY VERIFIED.** Free plan: 10,000 credits/month (3 custom voice slots: UNVERIFIED per reviewer); no commercial license [48]. Credit rollover does not apply to free tier [49]. Characters-per-credit not stated on pages read (UNVERIFIED; commonly 1 credit = 1 character, and Flash v2.5 is cheaper, "50% lower per character for API generations" per docs) [50]. API key: requests use `xi-api-key` [51]; whether the free plan gets API access is not stated on the pricing page (UNVERIFIED, one secondary source says yes with limited usage) [48][52]. German `de` is supported by Eleven v4/v3/Multilingual v2/Flash v2.5 [50]. Terms: free users "may only use the Services for non-commercial purposes", personal email required [53]; content from a free plan, or created without signing in, "must" be attributed by including "elevenlabs.io" or "11.ai" in the title when published; "The free plan does not include a commercial license" [54]. Private household playback is arguably unpublished, but at 30 s cadence 10,000 characters would be used up in well under a day (arithmetic: 2 nearest aircraft x ~100 chars each), so it is unusable as the always-on voice. It is a cloud dependency with an account, so it also conflicts with the "no contracts" constraint in spirit.
- **Old iPad Safari `speechSynthesis`:** Supported since iOS 7 per Can I Use [55]. But German voices are a problem: an Apple Developer Forums thread (Jan 2023 to Nov 2024) reports that on iOS 16 `getVoices()` returned only the "Eloquence" novelty voices (Eddy, Flo, Grandma, Grandpa, Reed, Rocko, Sandy, Shelley) though Anna, Markus, Petra, Siri, Viktor, Yannick were installed; worked on iOS 15; on iOS 18 "no German quality voice left ('Anna' has gone)". An Apple engineer replied that "only the pre-installed voices are available" in Web Speech and downloadable ones are not [56]. Another thread reports ~3 s lag switching to the Anna voice on iOS 15/16 on a physical device [57]. That the first `speak()` must come from a user gesture is stated only by a secondary guide (UNVERIFIED against WebKit) [58]. For iPads stuck on iOS 12 (e.g. iPad Air 1/mini 2-3, my inference) I found no German voice data at all.
- **Autoplay: VERIFIED.** Apple: in Safari on iOS (including iPad), preload and autoplay are disabled; `play()`/`load()` are inactive until the user initiates playback; applies to `<audio>`, `<video>` and Web Audio [59]. WebKit (iOS 10): only silent/muted `<video>` may autoplay; `play()` must be called from a `touchend`/`click`/`doubleclick`/`keydown` handler, not from e.g. `canplaythrough`; unmuting without a gesture pauses [60]. The archived Apple doc is older; the WebKit 2016 post is the newer statement; both agree. Common pattern (inference): one "Ton aktivieren" tap on page load that plays a short silent/real clip to unlock the audio element/AudioContext, then later programmatic playback from the same element generally works on iOS (not verified in these docs).

## Implications for the decisions

- **airspace-jy8hz (positions and routes):** adsb.lol as primary holds (keyless, ODbL; verified live). Change: airplanes.live must NOT be the keyless secondary (reports of 403 for non-feeders; official page unverified); replace by OpenSky with a registered OAuth2 client (4000 credits/day covers 2880 polls/day of a 1-credit bbox) or accept a single-source design with stale-state fallback. Radius is an integer nm (use 17), `dst` is nm, `flight` is space-padded, `category`/`r`/`t`/`geom_rate` may be missing. Route: keep the adsb.lol routeset (POST, max 100 planes, plausibility flag is weak and cached from the first caller) and adsbdb (keyless, rate limit undocumented, data not to be redistributed). ADR must record ODbL attribution and the planned future API-key requirement.
- **airspace-h76v2 (type, class, airline tables):** Prefer live `t`/`r` from adsb.lol, and CC0 VRS standing-data for airline/type tables; OpenFlights airlines.dat works (ODbL, 2012 snapshot, stale). Do not ship ICAO Doc 8643 or Mictronics/tar1090-db data until their terms are confirmed. A1-A7 meaning confirmed (A1 light, A2 medium 1, A3 medium 2, A4 high vortex, A5 heavy, A6 high performance, A7 rotorcraft); category is often absent.
- **weather-yttgx (weather and sun):** Open-Meteo holds (keyless, fields verified, WMO mapping ours to write, CC BY attribution link required, 15 min update interval, poll every 10-15 min). Bright Sky is a valid DWD-station fallback but uses `condition`/`icon` strings instead of WMO codes and needs DWD source credit. `is_day` is available, so a separate sun source may be unnecessary.
- **sky-scene-xczgm (German speech):** Piper holds but with changes: use `OHF-Voice/piper1-gpl` (GPL-3.0; rhasspy/piper archived), voices thorsten/kerstin are CC0; run it server-side and send audio to the iPad. ElevenLabs free tier does not fit (10,000 credits/month, non-commercial, attribution rule, cloud account). Browser `speechSynthesis` on old iPads is unreliable for German (voice list issues on iOS 16-18) so it is not a safe primary. Audio must start from a user gesture: add a one-time "Ton einschalten" tap that unlocks the audio element.
